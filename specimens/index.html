SYSTEM--FORM Test 01 — Industrial Robotics

  • [ MODEL: Gemini 3.1 Pro ]
  • [ SKILL: SYSTEM//FORM ]
  • [ CAPTURED: 2026-08-26 ]
  • [ ASSETS: 1 ]

Prompt, verbatim

Create a single-page landing page for **KINETIC FOUNDRY**, a fictional industrial robotics company that builds modular robotic work cells for small and mid-sized manufacturers.

Use the supplied SYSTEM//FORM skill as the governing design system.

### Required content

**KINETIC FOUNDRY**

**Automation built for factories that change.**

Modular robotic work cells designed to be reconfigured as production demands evolve.

**KF / CELL 04**

Payload: 35 kg  
Reach: 1,850 mm  
Repeatability: ±0.05 mm  
Configuration: 6-axis  
Deployment: Modular

Include:

- hero
- product overview
- technical specifications
- three capabilities
- deployment/process section
- final contact CTA

### Direction

Do not imitate a conventional robotics or SaaS website.

The product and its real specifications should become part of the visual architecture.

Use technical graphics only where they communicate actual supplied information.

Do not invent additional specifications, certifications, performance claims, customers, statistics, coordinates, or operational data.

### Evaluation target

This is SYSTEM//FORM operating on its natural subject matter.

The result should demonstrate the design system without relying on generic futuristic, cyberpunk, or industrial-tech tropes.

SPECIMEN 02 / c4f3e77a

Rivet Supply Co

  • [ MODEL: muse-spark-1.2 ]
  • [ SKILL: working-print ]
  • [ CAPTURED: 2026-08-22 ]

Prompt, verbatim

Create the RIVET SUPPLY CO. product-launch landing page using:

1. the supplied active design skill as the governing visual language,
2. the Landing Page Artifact Standard as the functional and medium-level constraint system,
3. the RIVET SUPPLY CO. brief as the project-specific source of truth.

Do not introduce a second visual system outside the active design skill. The artifact standard governs usability, responsive behavior, hierarchy, interaction, and landing-page requirements; it does not override the design skill's visual grammar.

Build a polished, complete landing page rather than a style sample or component inventory.

Prioritize:

- strong product hierarchy
- commercially useful information
- clear primary shopping action
- material and construction credibility
- product imagery treated as specimens or objects of inspection
- meaningful variation in scale, density, and composition
- responsive behavior that preserves the intended hierarchy

Include all required content from the brief. You may create plausible fictional product names, item numbers, prices, specifications, shipping language, and supporting copy where the brief leaves those details open.

Avoid generic ecommerce defaults, repeated rounded cards, conventional Shopify composition, artificial heritage styling, and visual decisions that are not justified by the active design skill.

The final artifact should unmistakably express the supplied design skill while still functioning as a clear, persuasive landing page.

SPECIMEN FILE 04

SPECIMEN 04 / ac609536

Night Shift

  • [ MODEL: ox-alpha ]
  • [ SKILL: meridian ]
  • [ CAPTURED: 2026-08-20 ]

Prompt, verbatim

NIGHT SHIFT — Independent Radio 91.3 FM

Tests: broadcast identity, live media state, programming schedules, counters, editorial content, atmospheric branding.

---

Create a complete, polished fictional website for an independent late-night radio station called:

NIGHT SHIFT

91.3 FM

Apply the supplied Solari UI/UX Design Skill as the governing design system.

This website should act as a flagship demonstration of how the Solari system can create a contemporary cultural brand without becoming an airport parody, retro novelty site, or generic dark music website.

CORE CONCEPT

The website should feel like:

"What if an independent midnight radio station built its digital identity around a living mechanical broadcast board?"

NIGHT SHIFT broadcasts music, interviews, live sessions, experimental programming, and overnight specialty shows from midnight until sunrise.

The result should feel:

- nocturnal

- analog

- atmospheric

- independent

- intelligent

- understated

- slightly mysterious

- editorial

- premium

Do NOT make it feel like an airport.

Avoid:

- aviation references

- departure terminology

- synthwave clichés

- neon gradients

- glowing waveform backgrounds

- cyberpunk

- glassmorphism

- generic streaming-app cards

- fake vintage radio decoration everywhere

The split-flap mechanism should feel native to the station's identity because programming, tracks, listeners, timestamps, and broadcast state are constantly changing.

TYPOGRAPHY

Use:

Space Grotesk 500/700

for every character inside a split-flap cell.

Use:

Space Mono 400/700

for labels, timestamps, metadata, navigation, controls, and tertiary information.

All characters inside flap cells must remain uppercase.

HOMEPAGE

A-01 / NOW PLAYING

Make the live broadcast state the dominant visual element.

Show:

NOW PLAYING

THE MIDNIGHT

SUNSET

The artist and track title should be rendered through large display-scale split-flap characters.

Also show:

STARTED

11:37 PM

ENDS

11:43 PM

PROGRAM

NIGHT DRIVE

HOST

ELLIS

Do not create one large fake flipping card.

Every character must exist as an independent physical flap cell with its own top half, bottom half, center seam, and hinge animation.

A-02 / LIVE AUDIENCE

Show a live listener count:

001284

LISTENING NOW

Use display-scale numeric flap cells.

Only digits that actually change should flip whenever practical.

Simulate restrained listener movement over time.

Example:

001284

↓

001291

↓

001287

Do not animate the entire number when only one or two digits changed.

A-03 / UP NEXT

Create a structured programming board:

TIME | ARTIST / PROGRAM | HOST | STATUS

Example:

11:43 PM | CHROMATICS — SHADOW | AUTOMATED | NEXT

11:48 PM | NIGHT DRIVE | ELLIS | QUEUED

12:00 AM | AFTER HOURS | MARLOW | LIVE SESSION

01:00 AM | DEAD AIR | KLINE | SCHEDULED

Statuses should use standard-scale split-flap cells.

Use restrained semantic status colors only on landed flap text.

Do not apply colored row backgrounds.

B-01 / TONIGHT'S SCHEDULE

Create an overnight schedule covering approximately:

10 PM → 6 AM

Possible programs:

NIGHT DRIVE

AFTER HOURS

DEAD AIR

TRANSMISSION

THE LONG WAY HOME

FIRST LIGHT

Present the schedule as a precise programming grid rather than a collection of cards.

Each program should include:

TIME

PROGRAM

HOST

FORMAT

STATE

The current show should visibly advance as simulated time changes.

B-02 / RECENTLY PLAYED

Create a restrained archive containing:

TIME | ARTIST | TRACK | RELEASE | YEAR

This section should prove that the system can support dense editorial data without turning every row into a giant flap display.

Use normal typography for records that are no longer changing.

Only stateful or newly updated values should invoke the mechanism.

C-01 / STATION SIGNAL

Create a compact station-state section showing:

ON AIR

SIGNAL

STUDIO

SOURCE

LOCAL TIME

Example:

ON AIR

YES

SIGNAL

NORMAL

STUDIO

A

SOURCE

LIVE

Use micro and standard split-flap components appropriately.

Do not use glowing status dots as the primary state language.

C-02 / STATION STORY

Create a quieter editorial section explaining the fictional station.

Possible headline:

"Independent radio for the hours nobody owns."

Explain:

- the station's overnight programming philosophy

- why it broadcasts after dark

- its relationship with local musicians

- live studio sessions

- listener-supported programming

This section should use normal readable typography.

Do not force split-flap components into static prose.

D-01 / NAVIGATION

Navigation:

LIVE

SCHEDULE

ARCHIVE

SESSIONS

ABOUT

When the active section changes, use a subtle micro-scale flap interaction.

Do not use a sliding underline as the primary transition.

D-02 / DEMONSTRATION CONTROL

Because this is a showcase website, include one restrained demonstration control:

ADVANCE TRACK

Activating it should:

- move the current track into Recently Played

- promote NEXT into NOW PLAYING

- update timestamps

- change the following queue

- trigger appropriate flap animations

The interaction should make the Solari mechanism immediately testable without feeling like a developer demo panel.

SPLIT-FLAP MECHANISM

Implement one reusable flap primitive and use it throughout the site.

Every flap must include:

- separate top and bottom halves

- exact horizontal center seam

- clipped duplicate glyph halves

- slightly lighter flap face than the board housing

- perspective on the parent

- top-down rotateX hinge motion

- correct stacking during transition

Never rotate the entire cell.

Never replace the physical flip with:

- opacity fades

- slides

- scale animations

- spring motion

- color swaps

DISPLAY SCALE

Use for:

- artist

- track title

- listener count

Use 3–4 intermediate character flips before landing.

STANDARD SCALE

Use for:

- schedule states

- broadcast states

- action confirmations

Use 2–3 intermediate flips.

MICRO SCALE

Use for:

- navigation

- tiny state changes

- compact counters

- small controls

Use one direct physical flip with no clatter sequence.

STAGGER

Characters update:

LEFT → RIGHT

When several records update:

TOP → BOTTOM

Do not refresh the entire board simultaneously.

IDLE LIFE

Every 20–40 seconds, allow one isolated flap to perform a quiet resettle.

Never animate multiple idle cells at the same time.

Keep this rare.

RESPONSIVE REQUIREMENT

Desktop should feel like a spacious live broadcast console translated into a public website.

On mobile preserve:

PROGRAM → STATE → TIME → DETAIL

Do not convert every schedule row into rounded cards.

Allow controlled horizontal scrolling for dense programming boards when necessary.

Respect prefers-reduced-motion.

The final result should feel like a real independent radio station commissioned a world-class digital identity.

Filing process

  1. An HTML output is dropped into the local Studio workbench.
  2. The operator files it with a title, the full prompt, the model, and the skill or system used.
  3. Any photos or art the page needs are filed alongside it; references inside the HTML are rewritten to the archived copies.
  4. The vault sanitizes the file (strict content-security policy, scripts disabled) and pins it to the board.
  5. Nothing is edited after filing. Specimens are shown as they shipped.
